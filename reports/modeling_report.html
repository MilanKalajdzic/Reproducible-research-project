ETF Trend Prediction — Modeling Report

MLP signal classifier and LSTM value regressor on European ETFs

Author

Published

1. Overview

This report documents the modeling stage of the ETF trend-prediction project. Building on the preprocessing pipeline described in the data preparation report, we train two neural architectures end-to-end on each ETF and benchmark them against a passive buy-and-hold baseline:

  • MLP signal model — a small multilayer perceptron that predicts the next-day trend direction Γ(t) ∈ {+1, −1} as a binary classification target.
  • LSTM value model — a recurrent network that regresses next-day Close from a 20-day look-back window of features; the predicted return is converted to a ±1 trading signal at inference time.

Both models are evaluated with an expanding-window walk-forward validator so every test fold is strictly out-of-sample. Per-fold metrics, daily signals, and equity curves are persisted for every ticker.

2. The two models

2.1 MLP signal model — MLPSignalModel

The MLP treats trend prediction as direct binary classification: given the scaled indicator vector for day t, predict whether Γ(t) = +1 (up) or Γ(t) = −1 (down).

Architecture (src/etf_predictor/models/mlp_signal.py):

Input (n_features) → Linear(128) → ReLU → Dropout(0.2)
                  → Linear(64)  → ReLU → Dropout(0.2)
                  → Linear(1)   → Sigmoid

Training details:

  • Loss: BCEWithLogitsLoss after mapping {−1, +1} → {0, 1}.
  • Optimiser: Adam, lr = 1e-3, weight_decay = 1e-5.
  • Batch size: 64, epochs: 30, seeded with random_state=42.
  • Inference: P(Γ = +1) ≥ 0.5 → signal = +1, otherwise −1.

The network is intentionally small so that it can be re-trained from scratch on every fold inside the walk-forward loop without a GPU.

2.2 LSTM value model — LSTMValueModel

The LSTM is trained as a regressor on the next-day closing price, not as a classifier. This more closely mirrors the design choice in Sagaceta-Mejía et al. (2024) where the recurrent network learns the price dynamics directly and a trading signal is derived from the implied return.

Architecture (src/etf_predictor/models/lstm_value.py):

Input (batch, seq_len=20, n_features) → LSTM(hidden=64, layers=1)
                                       → take last timestep
                                       → Dropout(0.1) → Linear(1)

Training details:

  • Target: scaled next-day Close (min-max scaled on the training fold; min/max stored so predictions can be back-transformed).
  • Loss: MSELoss in the scaled price space.
  • Optimiser: Adam, lr = 1e-3, weight_decay = 1e-5.
  • Batch size: 64, epochs: 20, sequence length: 20 trading days, seeded with random_state=42.

Signal derivation at inference:

\[ \hat{r}_t = \frac{\hat{\text{Close}}_{t+1} - \text{Close}_t}{\text{Close}_t}, \quad \text{signal}_t = \begin{cases} +1 & \hat{r}_t > 0 \\ -1 & \text{otherwise} \end{cases} \]

To predict for the very first row of a test fold, the validator passes the tail of the training set (the most recent sequence_length rows) as history, ensuring that no test-fold prediction is wasted on the warm-up window.

2.3 Why two architectures?

  • The MLP captures point-in-time pattern recognition across the ~260 indicators built in the preprocessing stage.
  • The LSTM captures temporal dependence across the trailing 20-day window of those same indicators and is anchored to the real price target rather than the noisy ±1 label.

Both models emit the same ±1 signal schema, so they plug into the same walk-forward harness and the same equity-curve evaluator.

3. Walk-forward validation

The validator (src/etf_predictor/models/walk_forward.py) implements an expanding-window scheme:

  • Initial train window: 750 rows (≈3 years of trading days).
  • Test window: 120 rows (≈6 months) per fold.
  • After each fold the test slice is appended to the training pool and the model is re-fit from scratch on the expanded history.
fold 1:  train = [0 : 750]            test = [750 : 870]
fold 2:  train = [0 : 870]            test = [870 : 990]
fold k:  train = [0 : 750+(k-1)·120]  test = [750+(k-1)·120 : 750+k·120]

For each fold the validator records:

  • signal ∈ {+1, −1},
  • actual_return = next-day simple return on unscaled Close,
  • strategy_return = signal * actual_return,
  • and per-fold metrics: directional accuracy, hit rate, mean return, annualised Sharpe.

This means every test prediction is strictly out-of-sample: at the moment the model predicts day t, it has only seen days < t.

3.1 Why expanding (not sliding)?

An expanding window lets each successive model benefit from the full history while still respecting causality. For financial time series this trades slightly older training context for a larger, more diverse training set as the backtest progresses — which we judged to be the right trade-off for these mid-frequency directional signals.

4. Equity-curve construction

After all folds finish, the per-day strategy returns are compounded (src/etf_predictor/models/equity.py):

\[ \text{Equity}_t = \prod_{s \le t} (1 + r_s^{\text{strategy}}) \]

starting at 1.0. The buy-and-hold baseline tracks Close_t / Close_0 on the same test index.

Summary statistics computed for every model and the baseline:

  • total_return, annual_return, annual_vol
  • sharpe = annual_return / annual_vol
  • max_drawdown (peak-to-trough)
  • hit_rate (fraction of positive return days)
  • n_days (number of test days actually traded)

Key takeaways from the table:

  • LSTM wins on Sharpe in 3 of 4 tickers (EUFN, FEZ, IVV vs MLP), driven by the price-anchored target and the temporal context window.
  • Both models beat buy-and-hold on the two European sector/large-cap ETFs (EUFN, FEZ) but lose to it on the broad IEUR and the trending IVV.
  • Drawdowns are model-dependent: the LSTM occasionally accepts larger drawdowns (EUFN −35%) in exchange for higher upside, while the MLP tends to keep drawdowns slightly smaller but at the cost of much lower returns.
  • Hit rates cluster around 48–53% across the board — i.e., the signals are only marginally better than coin-flips on a per-day basis, but the magnitude of correctly-called moves drives the Sharpe advantage where it appears.

6. Reproducing the results

# from the project root
PYTHONPATH=src python scripts/run_modeling.py
# or simply
make modeling

Useful CLI flags:

# Smoke test — 3 folds only
PYTHONPATH=src python scripts/run_modeling.py --max-folds 3

# Train a single ticker with custom epochs / look-back
PYTHONPATH=src python scripts/run_modeling.py \
    --tickers FEZ --mlp-epochs 50 --lstm-epochs 30 --lstm-seq-len 30

Each run regenerates:

  • reports/figures/equity_<TICKER>.png
  • reports/figures/fold_accuracy_<TICKER>.png
  • reports/results/<TICKER>_walkforward_metrics.csv
  • reports/results/<TICKER>_<model>_folds.csv
  • reports/results/<TICKER>_<model>_predictions.csv
  • reports/results/<TICKER>_equity_curves.csv

7. Limitations & next steps

  • Transaction costs and slippage are not modeled. With a daily ±1 signal that frequently flips, real-world fills and the bid/ask spread would erode a meaningful slice of the reported Sharpe — most aggressively on the LSTM’s higher-turnover folds.
  • Position sizing is binary. A confidence-weighted sizing scheme (e.g. scaling by predicted probability or predicted return magnitude) would likely smooth the equity curves and improve risk-adjusted returns.
  • No hyper-parameter search. Architecture sizes, epoch counts, dropout, and sequence length are fixed at sensible defaults. A walk-forward-aware tuning loop (e.g. nested CV on the training block) would be the natural next step.
  • Single seed. Each fold is trained from a single seed; reporting mean ± std across multiple seeds would tighten the conclusions, particularly on the borderline tickers (IEUR, IVV).
  • Feature set is shared across models. The MLP could benefit from feature selection (e.g. mutual-information filter on the training fold), while the LSTM might prefer a smaller, less redundant input vector.
